# 蓝色特权对比表按列对齐

## 原因与来源

原“列背景叠放 + 按行内容”由83254dc（2026-10-27 19:06）引入，用于保持VIP整列背景。上一轮容器评估确认了背景职责，却未对齐用户提供的RevenueCat按列编辑结构。这不是默认展开图层引入的变化。

本轮仅修改蓝色特权表：横向布局容器下有特权、非会员、VIP三列纵向布局容器，各列包含对应的文字或图标单元格。复用普通Stack与Button，不把参考模板的图层别名冒充新组件类型。

## 闭环清单

| 编号 | 问题 | 处理 |
|---|---|---|
| CT-01 | 空背景容器与内容按行分离，选择范围不符合按列配置预期 | 改为三列真实内容；移除空背景叠放与空非会员占位。VIP列自己承载背景和单元格 |
| CT-02 | 按列拆分可能损失权益行点击范围或造成错行 | 保留原行ID和动作；三个单元格共同保持行高、可见性和动作配置，文字/图标样式保持独立 |
| CT-03 | 既有文档与复制表格可能损失配置或联动原件 | 旧标准结构保守转置，保留内容/叶节点ID/商品数据；复杂自定义或引用待移除包装层的结构不强拆。整表复制重映射行关联，单独单元格复制不关联原表 |
| CT-04 | 重构不应更换当前蓝色样式 | 对比原真实HTTP渲染，18个可见文字/图标的坐标、宽高、文案和颜色一致；VIP整列背景可以直接编辑 |

## 验收边界

- 原生组件树、三列配置、原有动作及隐藏行、复制隔离、旧标准结构迁移均纳入自动化测试。
- 全部模板结构检查不等于所有模板的逐像素或SDK验收；本轮实际渲染验收限定蓝色特权表。
- 不批量保存或重置用户记录；不改其他模板视觉，不修改商品参数、页脚与挽留弹窗定义。
