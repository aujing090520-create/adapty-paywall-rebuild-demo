## 覆盖方法

独立清单不是从 Demo 自己的目录反推。`scripts/lib/component-structure-contract.mjs` 保存外部的 20 类组件、3 个快捷组合和专属子层契约；新增目录或内部类型却没有覆盖归属时，测试会失败。

`npm run audit:structure` 生成 [机器可读清单](component-structure-coverage.json)：32 种内部类型、87 份模板定义的父子约束、商品记录和已配置导航目标。87 包含 41 份参考图库定义、4 份 HT 定义和 42 份兼容定义；不代表逐张在原站重建了 87 张模板。节点数和源码哈希以机器清单为准。

本次续批已重新只读采集 [40 份完整原站层级](reference-structure/revenuecat-hierarchy-2026-10-26.json)，包含真实缩进、顺序、父子关系和已展开状态；另检查 7/8/9 的 ON 和 12 的 Standard，并恢复原预览状态，原站仍为 Saved。此前平铺记录不足以证明父子边界的问题已解除。

旧蓝图确实丢失了固定区域和状态归属。本批按逐模板边界修复，不统一把底部内容塞入 Footer。当前原子类型缺口、状态类型映射缺口及固定页脚数量差异均为 0；机器状态明确为 **`type-presence-only`，不是完整递归层级、字段或逐像素对齐认证**。

证据标记：**当前原站**是本轮只读界面，**文档**是本轮官方说明，**历史**是此前原端参数实验，**测试**是当前代码结构/渲染器断言，**本地画面**是本轮正常 HTTP 渲染。只有前者能证明本轮原站现场行为，测试通过不代替视觉验收。

### 快捷组合不是新原子组件

- 关闭/返回：`Stack 导航行 → Button → Icon`。按钮负责动作，图标负责形状和颜色；导航行属于版面逻辑，不自动变成固定 Header。
- 弹窗：`Button(OpenSheet) → BottomSheet → 内容`。只有有效绑定才显示弹窗画板和连线；删除/解绑与隐藏不是同一件事。
- 原站本轮 Add component 目录有 Bottom sheet；Footer 已存在时未再次出现。不能把条件隐藏误报为缺少组件，也不能把 Bottom sheet 快捷项误解为独立于按钮的全局弹窗。
- 商品组合：`Footer/Stack → Package → 叠放 Stack → 纵向 Stack → 文字`。外层 Stack 可以组织多个套餐，但 SKU、可选区域与双态不能交给外层通用容器。

## 明确没有闭环的范围

这些不计为“完全对齐”，也不因本轮测试通过而关闭：

1. 原生 iOS system navigation、原生安全区与平台钱包/恢复/兑换/真实购买。Demo 保留设计按钮和模拟路径，不伪造 SDK 能力。
2. 关闭/返回延迟显示：官方有此配置，但涉及阻止用户退出与平台审核风险，本轮没有擅自加入或改默认行为。
3. 深浅主题、全部富文本/字体上传组合、曲面遮罩、原站素材管理/转码、完整徽标与全部条件菜单。沿用 RC-01/05/06 未完成项，不声称已逐字段相同。
4. 每张参考模板的完整逐像素对齐、所有 SDK 版本和所有组件排列组合。参考图库第 38 项也不因为本地树结构合法就被标为原站完整验证。
5. 本批之外的全树逐节点匹配、所有 Package 内部徽标/选中标记、全部样式字段和图标字形的逐项核验，仍不能由“类型缺口为 0”替代。对应当前完整原站证据可继续逐组检查，不再依赖旧平铺清单。
