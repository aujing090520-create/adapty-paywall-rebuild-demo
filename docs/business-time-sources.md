# 倒计时与统一业务时间源

## 配置路径

1. 选择倒计时，设置“时间来源 → 业务时间源”。点击“配置业务时间源”，进入“工作区配置 → 业务数据 → 业务时间源”。
2. 添加来源：名称、接口数据键、适用范围、样例业务状态、样例到期时间（UTC）。范围支持活动统一到期、当前用户优惠到期、全局业务到期。
3. 返回属性，选择绑定时间源。组件只读显示接口数据键和统一的expiresAt时间字段；不重复设置接口地址或业务截止时间。手动deadline/start完整保留，可切回。
4. “条件与联动”选择“业务时间源状态”，引用相同来源，判断进行中、已到期或数据不可用。支持原有显示/隐藏/替换文字，以及按钮的禁用/启用。建议“不等于进行中 → 禁用购买”，同时覆盖到期与不可用；不自动修改用户原规则。

当前后台显示“Demo样例，未连接真实业务接口”。样例是本地配置数据，不是服务端活动管理。原有模板默认仍手动计时，不自动关联新活动、不重写原记录。

## 统一接入约定

宿主在已认证业务接入层取数，转换为下列结构；本轮没有新增真实接口请求、接口URL配置、密钥或真实用户信息。

```json
{
  "serverTime": "2030-01-01T00:00:00Z",
  "values": {
    "campaign.vip_sale": {
      "status": "active",
      "expiresAt": "2030-01-02T00:00:00Z"
    },
    "offer.current_user": {
      "status": "active",
      "expiresAt": "2030-01-01T00:20:00Z"
    }
  }
}
```

`status`为`active`、`ended`或`unavailable`。日期必须包含时区。`active`且时间到期也按ended展示；业务主动ended优先于未来截止时间。失败、缺数据、无效时间进入fallback，不伪装成00:00:00或自动续期。

```jsx
import {createBusinessTimeContext} from './src/builder/businessTime.js';

// 在收到每次已归一化的接口响应时调用一次，不在每次React渲染时重建。
const businessTime = createBusinessTimeContext(normalizedResponse);
<ComponentEditor {...editorProps} businessTime={businessTime} />;
// 独立展示也可直接传给PaywallPresentation或ComponentPreview。
```

适配层在收到响应时记录`performance.now()`，渲染以服务端时间加单调经过时间推进；共享响应跨画板、弹窗、返回预览不重置时间。新响应/当前用户切换时替换context对象。若没有服务端时间，则退回本地单调时钟，不能宣称服务端校时完成。

显式传入context后，缺键、接口失败必须返回unavailable或空values，绝不回退Demo样例。宿主负责接口刷新、取消/延期通知、当前用户鉴权和退出登录时清空旧context；运行时响应不写入付费墙配置。绑定同一接口数据键的不同屏幕读取同一业务值。

## 状态边界

- 倒计时是业务时间的消费者，不负责令活动、优惠或其他系统真正失效；支付和权益有效性由业务服务端判定。Demo只联动本地组件与模拟动作，不调用真实交易。
- 全局条件不依赖倒计时是否可见/是否在当前屏幕。无计时组件时，时间源规则仍会自然更新；点击动作还会即时重算规则，避免仅依赖上一帧的按钮状态。
- 同一响应可供多个倒计时使用。当前用户优惠的值由宿主按当前用户返回，不从模板读取用户ID，不在每次打开页面时重新起算有效期。
- 有引用的来源禁止删除，名称/数据键修改不改变来源ID。复制组件时携带用到的定义与规则；目标已有同key/同范围时复用，冲突时重映射，保留目标数据。
