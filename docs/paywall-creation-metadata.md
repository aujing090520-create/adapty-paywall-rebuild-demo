# 创建页配置边界

创建付费墙仅填写样式类型、样式名称、启用状态。类型使用用户提供的八个分类，与所选模板和SKU数据独立，不按分类自动替换画布。

桌面左侧是三项表单，右侧纵向排列“从空白开始”“选择模板”。窄屏自然排到表单下方。两条入口不校验名称，允许先进入样式编辑。

新建样式的构建器仅提供“确认样式”，点击后携带完整编辑结果返回创建页，不写记录。创建页展示已确认样式和“编辑样式”，再次编辑仍保留内容，修改后需重新确认。直接返回而未确认的样式不能创建。

创建页单独提供“创建”按钮，此时才校验类型、名称和样式确认状态；成功后保存完整文档与三项元信息，进入该记录基础设置。重复点击不会产生第二条，因为成功后离开创建页并切换为已有记录。保存失败则保留表单和样式。已有记录的构建器继续使用“保存”，不受此链路改动影响。

状态默认禁用。禁用记录保存为Inactive，启用记录保存为Draft，不因启用自动发布为Live。配置保存在paywall.config的styleType/name/enabled三个字段中。

## 已移除的旧创建配置

- 业务类型、公众号、业务场景、描述。
- 整张商品表：商品、优惠、优惠标签、默认选中、推荐标签（两态）、选中按钮文案、按钮标签类型、赠送，以及配套的编辑、复制和删除弹窗。
- offerRows/defaultProductId/products的创建默认值与新记录持久化。
- 没有调用方的linkedPackageNode旧联动函数。
- applyTemplate里点数模板回填旧商品表的特殊逻辑。
- 常规商品摘要从旧config.offerRows读取的回退逻辑。

## 保留的关系

当前原生构建器原本就通过模板文档与Package的dataKey关联document.products。这个关系不删除：SKU、金额、周期、默认选中及卡片内容继续在画布内配置。分类或名称改变，不会重写这些数据。

历史个人记录的旧config数据不批量删除，不强制重排其画布；复制时仅带入三项元信息与完整画布，不再携带旧商品表字段。新建和复制记录的商品摘要只读实际画布。

## 蓝色特权页商品归属修正

商品选择组位于页面正文、页脚之前，随正文滚动。固定页脚仅包含倒计时、协议、购买按钮和条款等底部内容。

旧版自动生成的蓝色模板如果将`products`直接放在该页面生成的Footer中，首次打开只将完整商品组移到Footer之前，原节点ID、所有卡片样式、SKU记录和选中配置保持不变；不自动写回浏览器存储，显式保存才持久化。使用版本标记只修一次；之后用户主动编排不会重复被改动。自定义页脚、其他模板和不符合旧结构指纹的内容不调整。

- 564项测试全部通过，包括空名称进入、样式确认不创建、再次编辑保留内容、最终创建唯一记录、原记录保存、复制及旧蓝色Footer精确修复。

- 商品实际父区为`nc-screen-content`，没有Footer祖先；预览滚动后商品底边到达页脚上沿，页脚位置不变。
