# 布局容器合理性与统一性评估

## 范围与判断标准

评估全部87份默认模板，基线1069个Stack容器。目标不是减少层数，而是明确每一层的排版、样式、尺寸、数据或交互职责。逐容器结果见[结构清单](layout-container-audit.json)。结构评估不等于87份模板全部逐像素验收。

| 编号 | 问题/判断 | 处理 | 状态 |
|---|---|---|---|
| LC-01 | 单子项不等于多余；商品选择边界、内部排版、背景、叠放、尺寸约束与显式占位各有职责 | 保留必要分组，不跨Package、屏幕、弹窗和页脚合并；保持组件名称展示规则，不用改名掩盖实际结构 | 确认不修改：保留职责边界 |
| LC-02 | 部分生成器空分组没有内容、外观、尺寸/留白约束或引用 | 清理新默认模板的31个空分组，仅限定已知生成器ID；保留商品选择组、固定占位、背景表面、数据列表和引用节点。不自动删除用户保存的空容器 | 已修改 |
| LC-03 | 蓝色特权页第1/3套餐将标签背景放进旧标签占位，层级比同级套餐多一层 | 在相同尺寸、无自定义属性且无引用时合并2个旧占位层；实际标签/参数ID、样式、顺序保留。旧文档只迁移一次，改变尺寸/可见性/留白、有额外子项或联动引用均保留。同步test3的实际标签隐藏目标 | 已修改 |
| LC-04 | 进入页面需要逐层展开才能定位组件 | 初次进入构建器图层默认全部展开；允许手动收起，选择组件或修改配置不重置收起状态。仅改变编辑器状态，不改变用户页面内容或预览流程 | 已修改 |

## 评估结果

- 保留1036个容器，清理/合并33个模板遗留容器；不以这个数量作为效果目标。
- 保留内容包括商品选择组、套餐内部排版、多个子项的排列/间距、独立背景、叠放定位、伸缩/留白、条件可见性与显式占位。
- 133个容器当前主要作为独立内容分组/排版配置入口，未发现足以证明应自动合并的重复职责；保留可编辑边界，不把“当前只有一个子项”作为删除理由。
- 既有用户记录不批量瘦身：只对明确旧HT标签占位指纹做保守迁移，不覆盖用户配置，不自动保存。

## 验证

- 586项自动化测试通过；覆盖旧标签迁移幂等、引用/自定义保护、用户空容器保留、图层初始展开和手动收起、test3隐藏行为及原价格/标签能力。
- 全部87模板结构检查：3764节点，0内部错误；参考样本类型和固定区域边界无新增缺口。此检查不宣称SDK或全像素等价。
- 蓝色特权页真实HTTP渲染前后对比19个套餐/标签/时长/价格框，设计像素x/y/宽/高最大差值0。
- 本地进入时56个可展开节点全部展开，146个图层可定位，已无旧标签占位行；手动收起在改价格后保持，标签与价格预览正常，控制台无错误。

## 复查入口
